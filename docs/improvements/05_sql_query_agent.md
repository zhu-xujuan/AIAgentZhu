# Agent: SQLクエリ生成エージェント (Step 5)

## 目的

ユーザーの自然言語質問からSQL検索条件（フィルター）を生成する。

## ファイル

- 実装: `services/agents/sql_query_agent.py`
- プロンプト: `services/llm/prompts/sql_query.py`
- テスト: `tests/test_sql_query_agent.py`

---

## 入力

```json
{
  "question": "田中さんの未完了タスクを教えて"
}
```

---

## 出力（JSON厳守）

```json
{
  "filters": {
    "owner_company": "string|null",
    "fact_type": ["task", "decision", "risk", "qna"],
    "status": ["open", "done"],
    "owner": "string|null",
    "date_from": "YYYY-MM-DD|null",
    "date_to": "YYYY-MM-DD|null"
  },
  "keyword": "string|null",
  "limit": 50
}
```

---

## ファクトタイプ検出キーワード

| fact_type | 日本語キーワード | 英語キーワード |
|-----------|----------------|---------------|
| task | タスク, TODO, やること, 対応事項, アクション, 宿題 | task, action, todo |
| decision | 決定, 決議, 決まった, 承認, 合意 | decision |
| risk | リスク, 懸念, 課題, 問題 | risk, issue |
| qna | 質問, 回答, Q&A, FAQ, 問い合わせ | question, qna, faq |

---

## ステータス検出キーワード

| status | 日本語キーワード | 英語キーワード |
|--------|----------------|---------------|
| open | オープン, 未解決, 未対応, 未完了, 進行中, 対応中, 作業中, 未着手 | open, pending, in progress, ongoing |
| done | 完了, 終了, 済み, クローズ, 解決済み, 対応済み | done, closed, completed |

## 日付抽出パターン

### 明示的な日付

```regex
# 標準形式
(\d{4})[-/](\d{1,2})[-/](\d{1,2})

# 日本語形式
(\d{4})年(\d{1,2})月(\d{1,2})日

# 月日のみ（現在年を補完）
(\d{1,2})月(\d{1,2})日
```

### 相対日付

| パターン | 処理 |
|---------|------|
| 今日 | 当日 |
| 昨日 | -1日 |
| 一昨日 | -2日 |
| 今週 | 月曜〜日曜 |
| 先週 | 前週の月曜〜日曜 |
| 今月 | 月初〜月末 |
| 先月 | 前月初〜前月末 |
| 今年 | 1月1日〜12月31日 |
| 去年 | 前年1月1日〜12月31日 |

### 日付範囲修飾子

| 修飾子 | 処理 |
|-------|------|
| 〜以降, 〜から | date_from に設定 |
| 〜以前, 〜まで | date_to に設定 |
| （なし） | date_from = date_to（特定日） |

## 担当者・会社名抽出

### 担当者（owner）
```regex
([^\s]{2,20})(?:さん|氏|様)(?:の|が|は)
担当(?:者)?[：:]?\s*([^\s、。]{2,20})
([^\s]{2,20})(?:が担当)
owner[:\s]+([^\s,]{2,30})
```

### 会社名（owner_company）
```regex
(株式会社[^\s　、。\nの]{2,20})
([^\s　、。\nの]{2,20}株式会社)
(合同会社[^\s　、。\nの]{2,20})
(有限会社[^\s　、。\nの]{2,20})
([A-Z][A-Za-z\s]{2,30}(?:Inc\.|Corp\.|Ltd\.|LLC))
```

---

## 件数制限（limit）抽出

```regex
(?:最新|直近|最近)の?(\d+)件
(\d+)件(?:まで|だけ|のみ)
top\s*(\d+)
limit\s*(\d+)
```

**デフォルト**: 50件
**最大**: 1000件

---

## キーワード抽出

質問から以下を除去した残りをキーワードとする:
- 質問パターン（「教えて」「検索」など）
- 抽出済みの owner/owner_company
- ステータスキーワード
- ファクトタイプキーワード
- 日付関連テキスト

**最小長**: 2文字
**除外ワード**: 「何」「どの」「どんな」「すべて」「全て」「全部」

## LLM統合

### LLM使用時
1. `format_sql_query_input()` でプロンプト生成
2. 今日の日付を渡して相対日付を解決
3. `ollama_client.generate_json()` でパース
4. 結果の正規化:
   - `fact_type`/`status` を配列に変換
   - 無効な値をフィルタリング
   - `limit` を範囲内にクランプ

### フォールバック
- LLM失敗時はルールベースパース
- 正規表現パターンマッチで抽出

## テストケース

### 正常系

```
Q: "田中さんの未完了タスクを教えて"
→ owner: "田中", fact_type: ["task"], status: ["open"]

Q: "先月のABC社に関する決定事項"
→ owner_company: "ABC", fact_type: ["decision"], date_from/to: 先月の範囲

Q: "リスクについて検索"
→ fact_type: ["risk"]

Q: "最新10件のタスク"
→ fact_type: ["task"], limit: 10
```

### エッジケース
- 空の質問 → 全てnull/空配列、limit: 50
- キーワードのみ → keyword に設定
- 複数ファクトタイプ → 配列に複数値

---

## ルール（厳守）

1. **推測しない**: 不明な値は `null`
2. **曖昧な場合は null**: 確信がなければ設定しない
3. **日付はYYYY-MM-DD**: 形式厳守
4. **fact_type/statusは配列**: 複数選択可能
